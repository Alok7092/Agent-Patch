Response — Kill Latency

Apple principle §1: "The moment lag appears, the feeling of directness falls off a cliff."

No press feedback on interactive cards

Critical

The .card elements in the triage queue respond on hover (translateY(-1px)) but have zero feedback on pointer-down. Apple mandates that feedback appears on touch-down/press, not release. A user pressing a card sees nothing until the click resolves and the detail panel updates — that dead moment breaks direct manipulation.

Fix: Add .card:active { transform: scale(0.98); transition: transform 80ms ease-out; } so the card responds the instant pressure is applied. Same for .nrow (dashboard rows), .chip (filters), and .stat (stat tiles).

Buttons lack active state

Important

The .btn class (primary, ghost) and .btn-block (login) define :hover but no :active transform or opacity change. Apple's tap model: highlight on touch-down, commit on touch-up. Currently buttons feel "spongy" — hover brightness change, but no physical depression.

Fix: Add .btn:active { transform: scale(0.96); opacity: 0.9; } with a very fast transition (~60ms). The press must feel instant.

Interruptibility — Never Lock Out Input

Apple principle §3: "Every animation must be interruptible and redirectable at any moment."

Change request drafting animation is non-interruptible

Critical

When "Draft change request" is clicked, a setTimeout(1100ms) fires and the UI shows a spinner. During this 1.1 seconds, the user cannot cancel the draft, navigate away safely, or interact with the drafting state. The spinner is a CSS @keyframes spin — a prescribed rotation that cannot be grabbed or redirected.

Fix: Replace the hard timer with a cancellable state machine. Show the spinner but allow a "Cancel" button. If the user navigates away during drafting, resolve gracefully. The spinner itself is fine as ambient feedback — it doesn't need to be interruptible since it's decorative, not interactive.

View transitions are instantaneous cuts with no interruptible crossfade

Critical

Switching between Dashboard, Security Notes, Landscape, and Approvals is a hard display: none toggle. There's no transition between states — the screen flashes to a new layout. Apple says "enter and exit along the same path." Here there is no path at all. Worse: if a user is mid-scroll on one view and accidentally clicks another nav item, there's no way to "undo" the navigation — the scroll position is lost.

Fix: Add a 150ms opacity crossfade between views. Use opacity: 0 → 1 with a critically-damped ease. Hide with visibility: hidden after fade completes, not display: none which can't be transitioned. Preserve scroll positions per view so returning doesn't reset the user's place.

Infinite perpetual animations cannot be paused

Moderate

The @keyframes pulse (live dot), @keyframes blip (AI-inferred system indicators), and @keyframes spin (drafting) run indefinitely. While decorative animations don't need to be "grabbed," perpetual motion consumes attention and GPU resources. Apple's guideline: motion serves utility, not decoration.

Fix: Limit pulse to 3 cycles then stop (use animation-iteration-count: 3), re-triggering only on state change. The blip animation on landscape cards should settle after the user has had time to notice it.

Spatial Consistency — Symmetric Paths

Apple principle §7: "If something disappears one way, we expect it to emerge from where it came."

Detail panel content swaps have no spatial origin

Critical

When a user clicks a card in the queue, the detail panel's innerHTML is replaced wholesale. The new content materializes from nowhere — it doesn't arrive from the direction of the card that was clicked. This violates "anchor interactions to their source." The user's eye must travel from card to detail content, and there's no visual bridge.

Fix: Fade the old detail content out (80ms), then fade the new content in (120ms). Add a subtle vertical slide (8px) in the direction of the selected card relative to the previous selection — if clicking a card below the current selection, new content enters from below, and vice versa. This is the "hint in the direction of the gesture" principle (§8).

Login-to-app transition has no spatial relationship

Moderate

The login card disappears and the app shell appears via class toggles. There's no spatial metaphor — the login doesn't "transform into" or "reveal" the app. Apple's precedent: unlock transitions on iOS scale/dissolve the lock screen away to reveal the home screen beneath it.

Fix: After login, scale the login card down slightly (0.96) while fading it to opacity 0. Simultaneously, fade the app shell in from opacity 0. Duration: ~300ms, critically damped. The login recedes; the workspace advances.

Materials & Depth — Translucency Conveys Hierarchy

Apple principle §12: "Build nav/toolbars as translucent layers with content scrolling underneath."

Good: Nav uses backdrop-filter correctly

Credit

The sticky nav uses backdrop-filter: blur(10px) with --header-bg: rgba(15,19,27,.82). Content scrolls beneath it. This is textbook Apple materials usage — a floating functional layer that brings structure without stealing focus.

Enhance: Consider adding a subtle top-edge highlight (border-top: 1px solid rgba(255,255,255,0.04) in dark mode) to give the material a faint lit edge, simulating light catching the surface.

Panels are flat — no depth hierarchy between stacked surfaces

Important

All .panel elements share the same background (--panel) and border treatment. The detail panel, side panels, and main content panels all sit at the same visual elevation. Apple's rule: "material weight encodes hierarchy" — structural regions (sidebars) use darker/heavier materials, while interactive elements (the detail) use lighter surfaces.

Fix: Give the detail panel a slightly elevated treatment — either a stronger shadow or a marginally lighter background than the queue panel. The dashboard stat tiles already do this partially with their gradient backgrounds. Extend this vocabulary: primary interaction surfaces float above navigation/chrome surfaces.

Hard borders instead of scroll-edge effects

Moderate

The .panel-head uses border-bottom: 1px solid var(--line-soft) as a hard divider between the header and scrollable content. Apple recommends: "Scroll edge effects, not hard dividers — fade a small blur/gradient mask where content meets floating chrome."

Fix: Replace the hard border under panel headers with a gradient mask on the scroll container's top: mask-image: linear-gradient(to bottom, transparent, black 12px). The divider appears only when content is scrolled underneath the header (use a scroll listener to toggle a class).

Typography — Optical Sizing & Scale

Apple principle §15: "Tracking is size-specific — never one value for all sizes."

Eyebrow text is too small and over-tracked

Important

The .eyebrow class sets font-size: 10.5px; letter-spacing: .16em. At 10.5px, this tracking pushes characters apart to the point of reduced legibility on lower-DPI screens. Apple's guidance: small text wants slightly positive tracking for legibility, but 0.16em is excessive — it's heading-label spacing applied at caption size.

Fix: Increase to font-size: 11px; letter-spacing: 0.08em. The slightly tighter tracking maintains the uppercase-label feel while keeping characters recognizable. Alternatively, bump to 11.5px and reduce to 0.06em.

External font dependencies will fail under CSP

Important

The HTML loads Space Grotesk, Inter, and IBM Plex Mono from Google Fonts via <link>. In a CSP-restricted context (or offline scenario), these will fail silently and fall back to system fonts. The design's character depends heavily on Space Grotesk's geometric display style — the fallback will look markedly different.

Fix: For the artifact/self-contained version, inline the font files as base64 @font-face declarations. For the production app (where CSP allows the Google Fonts origin), add font-display: swap to avoid invisible text during load. Consider whether the system font stack (-apple-system, system-ui) achieves similar goals with zero load cost.

Display type tracking is correct

Credit

The .verdict .lead and page headings use letter-spacing: -.02em and -.015em on larger sizes, loosening to normal at body size. This follows Apple's inverse tracking rule correctly — tighten large, leave body near zero.

Maintain: The type scale (10.5px mono labels → 14px body → 15-16px panel heads → 21-28px page heads → 26-36px stat numbers) is well-structured with clear hierarchy.

Reduced Motion & Accessibility

Apple principle §14: "Reduced motion doesn't mean no feedback — it means a gentler, non-vestibular equivalent."

prefers-reduced-motion kills ALL motion indiscriminately

Critical

The current rule: @media (prefers-reduced-motion:reduce){ *{animation:none !important; transition:none !important} }. This nuclear approach removes all transitions — including subtle opacity fades that Apple says should be preserved. A user who enables reduced motion still benefits from 200ms crossfades. Killing transitions also removes hover state changes, making the interface feel broken rather than gentler.

Fix: Replace the blanket kill with targeted overrides. Remove springs, slides, and bounces. Keep short opacity/color transitions (≤200ms). Keep transform transitions that are purely scale-based (press feedback). Remove translateY hover lifts. Replace the pulse/blip keyframes with a static indicator.

No prefers-reduced-transparency or prefers-contrast support

Important

Apple explicitly calls out three independent signals: reduced-motion, reduced-transparency, and increased-contrast. The nav's backdrop-filter: blur(10px) with a semi-transparent background will be hard to read for users who need reduced transparency. No increased-contrast treatment exists.

Fix: Add @media (prefers-reduced-transparency: reduce) { nav { background: var(--base); backdrop-filter: none; } } and @media (prefers-contrast: more) { .panel { border-width: 2px; } .badge { border: 1px solid currentColor; } }

Gesture Feel & Boundaries

Apple principles §9-10: Rubber-banding at boundaries; gesture design details.

Horizontal ribbon scroll has no edge indicators

Moderate

The .ribbon (landscape impact strip) scrolls horizontally with no visual affordance at the edges. A user doesn't know there's more content to the right. Apple uses gradient edge masks to hint at scroll direction — content fades out at the clipped edge, telegraphing that more exists.

Fix: Add edge masks using mask-image: linear-gradient(to right, transparent, black 24px, black calc(100% - 24px), transparent) or overlay gradient pseudo-elements that show/hide based on scroll position.

Filter chips lack tactile press feedback

Minor

The .chip filter buttons in the Security Notes view change border-color on hover but provide no press-state feedback. Per Apple's tap model: highlight on pointer-down, commit on release, and allow cancel-by-dragging-away.

Fix: Add .chip:active { transform: scale(0.95); transition: transform 60ms; } and consider a brief background-color flash on selection to acknowledge the state change.

Summary of Priorities

The UI's visual craft is strong — the severity color system, panel layouts, and typography scale are well-considered. The primary gaps are all behavioral: missing press feedback, hard view cuts instead of crossfades, a blanket reduced-motion rule that removes all transitions, and the non-interruptible drafting flow. Fixing the five Critical items would transform the app from a well-styled static document into something that feels alive under the hand.

The single highest-leverage change: add :active scale transforms to every tappable element. It takes 10 minutes and immediately makes the entire interface feel responsive.
